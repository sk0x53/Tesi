The following chapter aims to discuss the various objectives that we want to achieve with this thesis, the dataset used 
to test and prove the objectives, in order to know if these are reached or not, the experimental setup on which the test 
are executed and the actual test performed, alongside their results.

\section{Goals}
    In order to prove that the instrumentation approach is valid, I have choosen 3 main goals :
    \begin{itemize}
        \item \textbf{Goal I} : The instrumented binary must be compatible with the original one.
            This means that the behavior of the program must be preserved after the instrumentation.
        \item \textbf{Goal II} : The instrumented binary must be compatible with AFL and AFL++ communication protocol.
        \item \textbf{Goal III} : Show taht instrumentation overhead is competitive with other binary only rewriters and lower
                        than dynamic binary translator.
    \end{itemize}

    In order to prove that the tool satisfy these goals,  experiments were conducted:
    \begin{itemize}
        \item \textbf{Experiment I} : Test the original binary and the instrumented binary with the same input and 
            without using a fuzzer in order to prove the behavior preservation of the program after the instrumentation 
            (Goal I)
        \item \textbf{Experiment II} : Perform a fuzzing campaign with 3 different instrumentations:
        \begin{itemize}
            \item AFL++ in QEMU mode
            \item ZAFL 
            \item Mine
        \end{itemize}
        The choosen fuzzer will be AFL++. This test aim to prove Goal II and Goal III.
    \end{itemize}

     \begin{center}
        \textbf{Experiment II}
    \end{center}
    The dataset used for the second experiment is LAVA-M \cite{lava}, in the same version used by ZAFL \cite{zafl}.
    This dataset is composed of 4 coreutils binaries (\textit{base64 , md5sum , uniq , who}), to which synthetic bugs 
    were added with LAVA framework.Each bug has an unique ID and is protected by a checksum.
    A input could trigger the synthetic bug if the random mutation could satisfy the checksum.
    If a specific bug is triggered, the unique ID of that bug is printed and then the program crash intentionally.\\ 
    The used coreutil version is the \textbf{8.24}.
    As reported by Chen et al.~\cite{Angora}, the LAVA-M version of \textit{md5sum} was modified incorrectly: 
    when run with the \texttt{-c} option, it crashes on every input. 
    This affects our second experiment, in which the fuzzing seed must be parsed with \texttt{-c}. 
    Since every input triggers a crash, the results for this experiment are not meaningful.
    The experiment is done with AFL++ version 5.03c and made across 24 hours fuzzing campaign with 3 different repetitions per binary tested.
